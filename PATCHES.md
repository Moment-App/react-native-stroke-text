# Local patches on `dev-macadam`

Nitrogen-generated files are regenerated by `pnpm run specs`, which **silently drops**
everything below. Re-apply and re-verify after every regeneration.

## 1. `HybridStrokeTextViewManager.kt` must be `public open class`

Nitrogen emits `public class`, which is final in Kotlin and cannot be extended by the
handwritten `StrokeTextViewManager`.

## 2. Backport of nitro PR #1502 — dangling View props reference (Android)

Files: `nitrogen/generated/shared/c++/views/HybridStrokeTextViewComponent.{hpp,cpp}`

`ComponentDescriptor::adopt()` (Android only) read props via
`getConcreteSharedProps()`. React Native 0.79 through 0.87 declare that as returning
`const std::shared_ptr<...>&` but build the reference from a temporary
`std::static_pointer_cast(...)`, so nitro reads a dangling `shared_ptr`. The resulting
undefined behaviour makes prop delivery unreliable: text renders while `strokeColor` /
`strokeWidth` arrive as their Kotlin defaults (`Color.TRANSPARENT` / `0`), so
`StrokeTextView.onDraw` skips the stroke pass and the outline disappears intermittently.

Fix: start from the stable `ShadowNode::getProps()` owner and cast the `shared_ptr` by
value. `HybridStrokeTextViewState` now takes its props by value and moves them.

Fixed upstream in `react-native-nitro-modules` 0.37.0. Drop this patch once the app can
move off 0.35.x — currently blocked by `@rive-app/react-native`, which peer-pins
`react-native-nitro-modules >=0.35.10 <0.36` on every published release.
